04 / WHERE TO USE THEM
PRODUCT + PERSONA GUIDE

CHAT, COWORK,
OR CLAUDE CODE?

  • Claude.ai Chat is for questions, research, and writing. You ask, it answers. Best when you need a quick result — draft a caption, research a topic, get feedback on an idea. The whole session is one conversation thread. Open it when you don't need Claude to build or create files — just respond.
  • Cowork is for longer working sessions where you're building something together over many back-and-forths. Think: working through a strategy, developing a course outline, refining your offer over 30 minutes of iteration. It holds context across the whole session and is built for depth, not quick answers.
  • Claude Code is for building things that actually run — skills, automations, tools, workflows. Claude doesn't just respond, it takes actions: writes files, runs code, installs things, creates working tools. Open it when the output isn't a document or answer — it's something that does something.

Quick rule: need an answer or draft — Chat. Need to think something through over a long session — Cowork. Need to build something that works — Claude Code.

05 / THE DECISION RULE
HOW TO CHOOSE

MATCH THE
WEIGHT TO THE WORK.

  • Use Haiku when: the task is fast and repetitive and you don't need it to be perfect. Summarizing 50 YouTube comments to find the best hook. Sorting leads by category. Auto-tagging content. Done in seconds, done in bulk.
  • Use Sonnet when: you're building, writing, or researching. Writing your LinkedIn post. Building your first Claude Code skill. Researching 10 competitors. Drafting your lead magnet. This is where the vast majority of your work belongs — it's fast enough to feel instant and smart enough to get it right.
  • Use Opus when: you need the AI to run a long sequence of steps on its own and you can't afford for it to fail in the middle. Overnight research agents. Multi-step automations with 20+ actions. Anything where you set it running, go do something else, and come back expecting it to be done correctly.
SONNET → OPUS

// UPGRADE WHEN YOUR TASK TAKES MORE THAN 5 MINUTES AND RUNS WITHOUT YOU

  • The upgrade signal: if your automation fails on the same step three times in a row, switch to Opus. If your task involves reading more than 20 pages of content, use Opus. If you need the result to be right without reviewing it yourself, use Opus.
  • What it costs: Haiku is roughly 60x cheaper than Opus per word processed. Sonnet sits in the middle. For daily building work, Sonnet is the smart default. Opus is a deliberate upgrade for when the job demands it — not the default.
06 / THE STAKES
WHERE THIS IS GOING

RIGHT NOW: ONE TASK.
NEXT YEAR: HUNDREDS AT ONCE.

  • Opus 4.8 introduced Dynamic Workflows: instead of one AI working on one task, you can now run hundreds of separate AI tasks simultaneously from a single session — like sending a hundred assistants to work on different parts of a project at the same time, and having them coordinate automatically when they're done. That's genuinely new.
  • Today, picking the wrong model costs you an hour on one task. When you're running 100 parallel tasks, the wrong model choice multiplies across all of them at once.
  • Opus also has a Fast Mode — it runs at 2.5× the normal speed by trading depth for pace. Depth means how long Opus spends considering your request before answering: in normal mode it checks more angles, catches more edge cases, and is less likely to miss something subtle. Fast Mode skips some of that. You get Opus-level capability on a task but closer to a smart first draft than a careful final answer. The tradeoff on cost: regular Opus runs at $5 per million words in, $25 out. Fast Mode is $10 in, $50 out — 2× more expensive, but 2.5× faster. Use it when the job is complex but time-sensitive and you're okay reviewing the output yourself. Use regular Opus when the result needs to be right without you checking it.
  • Anthropic is already building the next tier above Opus: Mythos-class models. More capable. Launching in weeks. The tiers are about to expand, not flatten — understanding the ladder now prepares you for every rung that gets added.
  • The builders who nail model selection this year will design better systems next year. The ones who don't will spend 2027 wondering why their automations keep failing at scale.

DYNAMIC
WORKFLOWS.

  • Claude Code already had a /goal feature — you describe what you want, one AI agent works on it autonomously until it's done. Useful, but a black box: you step away, you come back, and it either worked or it didn't. No way to check its reasoning, no visibility into where it went wrong. If you're trying to learn what Claude is doing, it's the worst possible mode.
  • Dynamic Workflows is the same instinct — "work on something big without me supervising every step" — but with two things /goal doesn't have: many agents working in parallel, and separate agents explicitly trying to find mistakes before anything gets delivered. It's more accurate. But it's just as opaque. Neither mode is right if you want to understand what happened.
WHAT IT IS
A TEAM, NOT ONE AI
Instead of one AI working through a task step by step, Dynamic Workflows spins up dozens of separate AI agents working on different parts of the job simultaneously — then has them check each other's work before anything lands.
WHEN TO USE IT
BIG JOBS THAT CAN'T FAIL
When the task is too large for a single pass — touching hundreds of files, auditing an entire project, or anything where one missed error ruins the whole result. If it would take a human team days, this is built for that.
WHAT YOU'D USE IT FOR
SCALE MOST PEOPLE DON'T HAVE YET
Full content audits across a large library. Scanning every page of a site for inconsistencies. Rewriting an entire course or product from scratch with quality checks on every section. 750,000 lines of code rewritten in 11 days — that's the category.
HOW TO TURN IT ON
ULTRACODE SETTING
Claude Code only — not available in chat. Open the effort menu inside Claude Code Desktop, the terminal, or VS Code and select Ultracode. Or just type "Create a dynamic workflow" as your prompt and it triggers automatically.
