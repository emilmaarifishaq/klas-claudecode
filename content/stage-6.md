## 🧠 Why a Game Beats Everything Else for Proof

![Why a Game Beats Everything Else for Proof](/images/stage6-game-proof.png)

> **You'll walk away with:** the reason a 20-minute game outperforms a polished website as proof you can build.

Here's the thing nobody tells beginners: **a game is the easiest impressive thing you can ship.** A classic like Pong is one self-contained web page — no database, no login, no payment. Claude can build a playable one in the time it takes to make coffee. Traditionally that's 4–6 hours of code. You're going to describe it.

But the *real* reason it wins is human:

- A website asks someone to "have a look." A game asks them to **play** — and they will.
- Nobody can argue with a game. It either runs or it doesn't. Yours runs.
- "I built a website" is forgettable. "I built a game — try it" gets opened, replied to, and shared.

You are not "learning game development." You're using the smallest possible project to prove the whole skill: **you direct, Claude builds.** Director, not typist.

## 🎮 Your First Classic

![Play Anywhere](/images/stage6-play-anywhere.png)

> **You'll walk away with:** a real, playable game running in your browser — built by describing it.

Pick one classic. Build it by describing it to Claude. Run the loop: play it, say what's wrong in plain words, repeat.

**Start prompts:**

> Build me a fully playable Pong game that runs in a single HTML file in the browser — no external libraries, no build tools. Two paddles (one keyboard, one basic AI), a bouncing ball, a score counter, and a "first to 5 wins" condition. Make it look clean and modern — dark background, neon accents. Open a live preview.

> Build me a fully playable Snake game that runs in a single HTML file. Smooth controls, growing snake, food that respawns, a score counter, game-over screen with restart. Clean dark design. Open a live preview.

> Build me a Tetris clone that runs in a single HTML file. Full piece set, rotation, line clearing, score, level speed increase. Clean modern look. Open a live preview.

**The loop:** play it → describe what's wrong → repeat. "The AI paddle is too easy," "the ball speeds up too fast," "the controls feel laggy" — that's the workflow.

## 🏆 Make It Yours

![Make It Yours](/images/stage6-make-yours.png)

> **You'll walk away with:** a personalised version with your name on it and a twist nobody else's has.

A generic Pong gets a polite nod. *Your* game — themed, named, with a mechanic you invented — gets played and shared. This step is where a build becomes content.

**Ideas for your twist:**

- A theme tied to your audience (a niche in-joke, a fitness theme, a business metaphor)
- A reverse rule, a power-up, a curveball, a "hard mode" toggle
- Your name on the title screen and a personal message on game-over

> Adding **"save the high score in the browser and add a Share button that copies the link"** turns a toy into a tiny viral loop.

**Prompts:**

> Reskin this game with a [theme] look — new colours, title, fonts, sound effects (use the Web Audio API, no external files). Add one twist mechanic: [describe your twist]. Put my name on the title screen.

> Add a persistent leaderboard that saves to localStorage, a Share button that copies the URL + score to clipboard, and a "hard mode" toggle. Keep it in the same single HTML file.

## ⚠️ What Beginners Get Wrong

![What Beginners Get Wrong](/images/stage6-beginners.png)

Three mistakes turn a 1-hour win into a 3-day spiral:

- **Building too big.** "An open-world RPG" will collapse. A classic (Pong, Snake, Tetris, a runner) finishes *today* and ships. Scope down, ruthlessly.
- **Trying to fix it by "coding."** When something's off, **describe the symptom** — "the ball passes through the paddle sometimes," "it lags after a minute." Don't open the file and poke at it.
- **Never sharing it.** A perfect game nobody saw is worth nothing. An ugly game 10 people played is proof, content, and leads.

> The fix for almost every "it's broken" moment is one sentence to Claude describing exactly what you observed on screen.

## 🍊 Full Walkthrough — Click The Target in One Sitting

![Full Walkthrough](/images/stage6-walkthrough.png)

> **You'll walk away with:** a complete, deployed, shareable game built in one sitting — every prompt, every file, every step, in order.

**Step 1 — Open a fresh folder and spec the game**

**Prompt:**

**Step 2 — Iterate 3–5 rounds**

## 🔧 Anatomy of a Good Game Spec (Copy This Pattern)

![Anatomy of a Good Game Spec](/images/stage6-game-spec.png)

> **You'll walk away with:** a reusable template for writing the first prompt for any of the 10 games — so you never stare at a blank Claude Code window again.

Every good game spec has five parts: **Name · Objective · Controls · Win Condition · Lose Condition**. Memorise this pattern — it works for every build in this course (offers, landing pages, agents, anything).

**The template:**

> Build me a fully playable [NAME] game that runs in a single HTML file, CSS and JavaScript inline, no build tools. Objective: [primary goal / player mission]. Controls: [input method + key bindings]. Win condition: [how to achieve victory / success state]. Lose condition: [how to fail / failure state]. Make it look [visual style]. Open a live preview.

The line "a single HTML file, CSS and JavaScript inline, no build tools" is the line that keeps Claude from over-engineering. Keep it in every game prompt.

## 🎯 10 Proven Games Prompts

**1. Idle Clicker Game**

> Build me a complete idle/clicker game that runs in a single HTML file in the browser, no build tools. Theme: [YOUR THEME]. Include: a big clickable main button that earns currency, at least 5 purchasable upgrades that auto-generate currency over time with rising costs, a prestige/reset mechanic that grants a permanent multiplier, and progress saved to localStorage so it survives a refresh. Make the numbers feel satisfying with clean formatting (1.2K, 3.4M). Stay in plan mode and ask me clarifying questions first.

**2. 2D Platformer**

> Build me a simple 2D side-scrolling platformer that runs in a single HTML file. Include: smooth left/right movement + jump (keyboard), at least 5 platforms of different heights, a collectible item that adds to a score counter, a simple enemy that patrols back and forth, and a "you win" state when all collectibles are grabbed. Clean pixel-art look. Stay in plan mode first.

**3. Word / Trivia Game**

> Build me a fully playable word trivia game in a single HTML file. Theme: [YOUR NICHE/TOPIC]. Include: 20 multiple-choice questions, a 30-second countdown timer per question, a score counter, a "you got it right/wrong" animation, and a final score screen with a Share button. Make it look polished — clean card UI, smooth transitions.

**4. Endless Runner**

> Build me an endless side-scrolling runner in a single HTML file. A character that auto-runs, tap/click or spacebar to jump, obstacles that scroll toward the player at increasing speed, a distance score, a high score saved to localStorage, and a clean game-over + restart screen. Give it a fun theme: [YOUR THEME].
