- The "before" and "after" of a design polish

## 🔬 Higgsfield — Deep Walkthrough

![Higgsfield Deep Walkthrough](/images/stage8-higgsfield.png)

> **You'll walk away with:** a working Higgsfield workflow — first image selected, first clip generated, first iteration done.

Higgsfield is currently the best tool for **cinematic human motion**. If your content involves people, action, or anything that needs to look like it was shot on a camera, this is your first stop.

### What it does well

- Realistic human motion from a single still image
- Camera movement controls (dolly in, pan, crane up — all described in text)
- Face and body consistency across multiple clips from the same anchor image

### The workflow

**Step 1 — Generate your anchor image.** Don't start with Higgsfield. Start with Midjourney or Flux to generate the exact face/character/scene you want as a base. High-res, portrait orientation, high detail.

**Step 2 — Upload to Higgsfield.** Go to app.higgsfield.ai, create a project, upload your anchor image.

**Step 3 — Write a motion prompt.** Describe what should move and how. Be specific about the camera, not the story:

> Close-up of a woman in her 30s, confident expression, slow dolly pull back revealing a minimalist office behind her, natural window lighting, photorealistic.

**Step 4 — Generate and evaluate.** First clip is rarely the keeper — you're evaluating whether the motion is clean and the character held. If yes, this is your foundation clip.

**Step 5 — Generate variations.** Same image, different camera move, different energy. You need at least 3 clips per character to have editing options.

## 🖼️ Image → Motion → Voice (The Cinematic Stack)

![Image → Motion → Voice](/images/stage8-cinematic-stack.png)

> **You'll walk away with:** the full pipeline from a single idea to a finished, voiced clip — knowing exactly which tool handles which step.

### The pipeline

```
Concept → Script → Storyboard (Claude) →
Anchor Images (Flux / Midjourney) →
Motion Clips (Kling / Higgsfield) →
Voiceover (ElevenLabs / OpenAI TTS) →
Assembly (FFmpeg via Claude Code)
```

### Each step, explained

**Concept → Script → Storyboard:** Claude Code handles all three in one session. Give it the topic, the audience, and the tone. Ask for a storyboard: scene-by-scene breakdown, each scene one clip, each clip one image prompt. This is the creative work — don't skip it.

**Anchor Images:** one image per scene. Consistency matters more than beauty. Use the same subject description (same hair, same clothing, same lighting) across all image prompts so clips cut together.

**Motion Clips:** upload the anchor image to Kling or Higgsfield, add the motion prompt, generate. Target: 5 seconds per clip. 3 clips = 15-second Short.

**Voiceover:** paste your script into ElevenLabs or use OpenAI TTS. Download as `.mp3`. Match the clip length.

**Assembly:** Claude Code + FFmpeg. Tell Claude: "Assemble these 3 clips with this voiceover. Add a 0.3s fade between clips. Export at 1080×1920 for Shorts."

## 🛡️ Faceless Shots Safety Guardrails

> **You'll walk away with:** a short checklist you run before publishing any AI-generated video — so you don't accidentally post something you'll regret.

AI video tools can produce content that looks real but isn't. This is a strength (production at scale) and a risk (misinformation, likeness issues, platform violations). The checklist is short:

**Before you post any AI video:**

1. **No real person's face without consent.** If you generated a face using someone's photo or likeness, don't publish without their explicit written permission. Use your own face (cloned) or a generated fictional character.
2. **No misleading context.** If the video looks like a real person said something they didn't, add a disclosure: "AI-generated content." This is increasingly required by platform policy and law.
3. **No platform-banned content.** Check the current content policy for the platform you're posting to. AI-generated nudity, political deepfakes, and synthetic news are banned on most platforms.
4. **Attribution for source material.** If you used someone else's video, audio, or image as a base, check the licence terms. Most Higgsfield/Kling outputs are safe — the training data is licensed. Uploading a celebrity photo is not.

## ⚙️ Airtable + n8n Batch Queue (Scaling to Volume)

> **You'll walk away with:** the architecture for a batch video production queue — so you can go from "one video per week, manually" to "ten videos per week, managed."

### The shape of the queue

**Airtable** holds the content calendar — one row per video, with fields for: topic, script, status (queued / generating / done / posted), image prompt, clip filenames, output filename.

**n8n** is the automation layer. A nightly workflow runs through every row where status = "queued":

1. Calls Claude (via API) with the script to generate the image prompt
2. Calls the image generation API (Flux, Midjourney) with the prompt
3. Calls the video generation API (Kling) with the image
4. When the clip is ready, updates the row status to "generating voiceover"
5. Calls OpenAI TTS with the script
6. When the voiceover is ready, updates status to "assembling"
7. Calls the FFmpeg assembly script (Claude Code, headless)
8. Updates status to "done" and stores the output filename

You review the "done" rows, approve, and post.

This is how you go from hobbyist to operator.

## 🎞️ Kling 4-Part Prompt Formula

> **You'll walk away with:** the 4-part formula for writing Kling motion prompts that produce consistently usable clips — and 5 proven examples you can modify.

The difference between a Kling clip that looks broken and one that looks cinematic is almost entirely in the prompt. Here's the formula:

**[Subject + action] + [camera movement] + [lighting / mood] + [technical style]**

**5 proven examples:**

1. > A woman walking slowly through a sunlit forest path, camera tracking alongside her at walking pace, golden afternoon light filtering through the canopy, cinematic 35mm, shallow depth of field

2. > A man typing at a laptop in a dark home office, camera slowly pushing in toward the screen, blue monitor glow on his face, high contrast, noir

3. > A coffee cup on a wooden table, steam rising, slow extreme close-up, warm morning light, soft focus background, documentary style

4. > A city skyline at night from a rooftop, timelapse-style clouds moving overhead, slow crane down to street level, wide angle, blue-black tones

5. > A hand placing a product on a white surface, camera at 45-degree angle, smooth dolly in, clean product photography lighting, no distractions

**The most common mistakes:**
- Describing narrative instead of camera ("the character feels anxious") — describe what moves, not what is felt
- Under-specifying camera movement — "the camera moves" is not specific enough; "slow dolly pull back" is
- Over-loading the prompt — pick one camera move, not three

## 🔄 Character Consistency — 3 Methods

> **You'll walk away with:** at least one method active for keeping your AI character looking the same across clips — the most important technical skill in AI video production.

The single biggest problem in AI video is character drift — your subject looks slightly different in every clip. The fix is one of three methods, from easiest to most powerful:

**Method 1 — Same anchor image, always**
Use the same source image for every clip in a project. This is the minimum. Kling and Higgsfield will maintain the character relatively well if the source image is the same. Use a high-res, front-facing, well-lit portrait.

**Method 2 — Reference image in every prompt**
Upload your anchor image alongside every new generation request (even if you're only changing the camera movement). The model uses it as a style reference. Works well with Midjourney (--cref flag) and Flux.

**Method 3 — Character sheet**
Generate a "character sheet" — 4–6 images of the same character in different poses and lighting conditions from a single prompt session. Use these as the reference pool for all subsequent generations. More work upfront, much more consistency across a long project.

AI video generators typically output at 512×512 to 1080×1920 depending on the tool. For Shorts this is fine. For anything longer-form or for archiving, upscaling is the move.

**The tools:**

- **Topaz Video AI** (desktop, paid) — the best quality upscaler. Takes an MP4, outputs at 4× resolution, AI-enhanced sharpness. Slow (10× realtime on CPU, 2× on GPU) but exceptional quality.
- **Real-ESRGAN** (free, open source) — good enough for most content. Claude Code can install and run it for you.
- **Kling/Higgsfield native export** — both tools now have internal upscaling at export. Use it. It's free.

**The Claude Code upscale workflow:**

> I have a video at 540×960 (file: clip.mp4). Upscale it to 1080×1920 using Real-ESRGAN. Install it if it's not installed, run it, save the output as clip_upscaled.mp4.

## 🎭 Cast Yourself in a Scene

> **You'll walk away with:** one clip of your own face or character in a generated AI scene — the move that makes AI video personal and therefore shareable.

Putting yourself in an AI-generated scene is the content move that performs best because it's personal, unexpected, and visually striking. It's also less work than a traditional photo shoot.

**Method 1 — Face swap (fastest)**
Generate the scene without your face. Use a face-swap tool (Akool, Remaker, or Higgsfield's face-swap mode) to place your face on the generated character. Takes 5 minutes. Works best if your source photo is high-res, forward-facing, and well-lit.

**Method 2 — Consistent character from your photo (best quality)**
Upload a photo of yourself to Midjourney (--cref) or Flux (IP-Adapter). Generate the scene with your likeness. Then animate with Kling. The character looks like you from the start — no swap needed.

**Method 3 — HeyGen avatar + AI background**
Clone your face and voice in HeyGen. Generate an AI background in Midjourney or Higgsfield. In HeyGen's compositor, place your avatar in front of the generated background. Most production-quality result.

**The first cast:**

> I want to appear in an AI-generated scene. I have a photo of myself (photo.jpg). Using [tool], place me in this scene: [describe the scene]. Walk me through the steps.
