## 🔥 DON'T WORRY! You Can't Mess This Up

The #1 thing I hear from beginners: *"What if I do it wrong, or break something?"*

You can't. Two reasons.

**1. There's no right way. There's your way.** Everything we teach is a starting point, not a rulebook. If you find something that works better for you than what's in a lesson, use it. That isn't doing it wrong. That's doing it right.

**2. You're not writing code. You're talking.** "Code" is in the name, but you'll basically never write any. You tell Claude what you want in plain English. Type it, or do what I do and use speech-to-text. Ramble, hand it a half-formed idea, say something vague and ask it to make it specific, or have it ask you questions until it knows enough. You don't need the perfect prompt. You need to start talking.

And it's hard to break. When something's off, you don't fix code or start over. You tell Claude what's working and what isn't, and ask it to update itself with what it just learned. That back-and-forth IS the work, not a sign you messed up.

You will learn how to use Claude Code the FASTEST simply by talking to it more. If you don't understand something, just ask Claude: what did it do and why — and READ the responses back to you. It's the best way to understand how Claude thinks and acts.

**Just start.**

## 🧭 From Chat to Claude Code: Why You're Here

> **You'll walk away with:** why the jump from a chat box to Claude Code is the whole point, in plain English.

![Chat vs Co-Work vs Claude Code](/images/stage1-chat-vs-claude.png)

You probably came from chat. ChatGPT, or Claude in a browser, asking questions and getting answers. Something told you to go further, but it isn't obvious why. Here's the why, in three steps.

**Chat. It tells you.**
You ask, it answers. Draft this email, explain this idea, write this snippet. Brilliant, but it hands you words and stops. You still have to go do the thing yourself.

**Co-work. It helps you make one thing.**
Co-work works with you inside one window and you watch a single thing take shape: a document, a chart, a draft you can poke at. It can even reach into a few of your tools. Better, because now you get something built, not just text. But it's still a workbench. You and Claude, shaping one piece, in a sandbox.

**Claude Code. It does the work.**
This is the leap, and it's the whole reason you're here. You describe the outcome and Claude actually builds it: real files on your computer, real programs running, a real product you can put in front of a paying customer. Not a description of the website. The website. That's the move. Chat tells you. Co-work helps you. Claude Code does it. Everything in this community lives in that third step.

**Why it feels strange at first:** you're used to copying answers out of a chat box. Here you stop being the person doing the work and become the person directing it. That instinct — describe, watch, react, ship — is what separates people who build from people who "always meant to learn."

## 🖥️ Installing Claude Code

> **You'll walk away with:** Claude Code installed and open on your machine, signed in, ready to take its first prompt. About 3 minutes start to finish.

![Installing Claude Code](/images/stage1-install.png)

Two ways in. **Pick the desktop app.** It's the same Claude Code engine the pros use — same power, same settings — just with windows and buttons instead of a black terminal screen. Most members never touch the terminal and never need to.

### Install the desktop app (do this — 3 minutes, five clicks)

1. Open **claude.com/download** in your browser.
2. Click **Download Claude Code** — pick **macOS** or **Windows** depending on your machine.
3. Open the file you just downloaded. On Mac, drag it to **Applications**. On Windows, run the installer.
4. Open the app. You'll land on a sign-in screen.
5. **Sign in** with your Claude account (same account as claude.ai). You'll see a clean window with one input box at the bottom. That's it — you're in.
6. **When it asks for a folder, create a new empty one** (call it `my-business`) and open it. That's your home base for everything you build in this course. Nothing needs to be inside it. Claude Code just wants a place to work.

### CLI option (skip if unsure)

Only if you're already comfortable in a terminal. Run `npm i -g @anthropic-ai/claude-code`, then run `claude`. No windows, no installer. You can pick this up later — you don't need it today.

### What beginners get wrong

- **Overthinking it.** There's no "environment setup," no SDK, no config file. Download, sign in, done.
- **Quitting at an error message.** Almost every install error is one click to fix. Screenshot it, post it in the community, move on. Someone else hit the same error yesterday — the fix takes seconds once another human sees it.
- **Thinking you must choose the terminal to be a "real" builder.** You don't. The app and the terminal share the same engine and the same settings, power no difference. Start with whichever you like simply because it's the easier on-ramp.

### Quick troubleshooting (95% of install issues fit here)

- **"Sign-in keeps failing."** Sign out of claude.ai in your browser first, then try the app sign-in again. Token mismatches resolve immediately.
- **"App opens but is blank."** Quit the app fully (Cmd+Q on Mac, right-click → Quit on Windows), then Open. The first time always asks for explicit consent.
- **"Git is required for local sessions."** You did nothing wrong. Git is a free tool Claude Code uses (to power the undo buttons). On Mac: open the Terminal app, type `git --version`, press enter. Your Mac will print a note like *"No developer tools were found, requesting install"* — that is the install dialogue, click Install.

## 🖥️ The Desktop App: No Terminal, No Fear

> **You'll walk away with:** the mental model that makes everything else in this course easy, plus a tour of every part of the app screen you'll use.

![Welcome to Claude Desktop App](/images/stage1-desktop-app.png)

The #1 thing that scares people off building is the terminal: that classic black screen with text. Here's the relief: **you don't have to use it.** The desktop app gives you identical power in a familiar window. And if you do ever want the terminal, it's just as capable, with lessons waiting.

Here's the mental model: one powerful engine, two ways to drive it. The terminal is the bare dashboard Claude Code was born with: lean, fast, and loved by people who like full keyboard control. The desktop app is that same engine with a friendly dashboard: buttons, a live file preview, your files in view. Identical power underneath. We start you on the app because it's the gentler one to learn on. That's the only reason.

### A tour of what's on your screen

When you open Claude Code, you'll see four areas. That's all you need to know:

- **Input box (bottom).** You type what you want in plain English. This is the only place you ever "command" the app.
- **Conversation area (middle).** Everything you've said and everything Claude has said back, scrolling. Claude's tool calls (file edits, terminal runs, browser opens) appear here as you watch — you see the work happen.
- **File / preview pane (side or full-screen).** Files Claude creates show up here. If you're building a website, a live preview opens here — you can click around it like a real user.
- **Settings (top-right gear icon).** Where your global CLAUDE.md, your skills, your MCPs, and your account live. You'll touch this twice in the next stage and then rarely again.

### The workflow, forever

Once it's open, this is every interaction you'll ever have with Claude Code:

1. **You type** what you want in plain English ("build me a one-page site for my bakery").
2. **Claude works** — you watch it think, create files, run things. The conversation area shows everything live.
3. **You see the result** — files appear in the side pane, a live preview opens, you click around.
4. **You react** — "make the header bigger," "I don't like the colours," "add a booking form" — and Claude updates it.

Results. That single shift is what separates people who build from people who "always meant to learn."

### What beginners get wrong here

- **Trying to memorize commands.** There are none. You talk to it in English.
- **Expecting it to be like a chatbot.** You're not getting answers — you're getting work done.

## 🛟 The Undo Button — You Can't Break Anything

> **You'll walk away with:** permission to stop being careful — because before you build a single thing, you'll know that every change is reversible and you can always go back.

The most common reason people freeze at the terminal: *"What if I break something?"* Let's kill that right now, before your first build — because the fear is the only real obstacle, and it's based on something that isn't true.

### You cannot permanently break anything here

Two safety nets are on by default:

- **/rewind** — Claude Code automatically saves a checkpoint *before every change it makes.* Type **/rewind** (or press **Esc** twice on an empty input) and you can roll back to any earlier point — restore the files, the conversation, or both. It's a time machine for your work, and it's already running.
- **Git** — a permanent "this worked" save you can always return to. You don't memorize commands; you just tell Claude **"commit this as a checkpoint"** and it's locked in.

### So here's the rule for the whole course

**Experiment freely.** The worst case of anything you try is "go back to the last checkpoint" — minutes lost, never your work. Careful people don't build faster. You have to know the undo button exists, it does. It's needed.

**Done when:** you know the two safety nets — /rewind to undo any change, and 'commit this as a checkpoint' for a permanent save — and you're cleared to experiment without fear.

## ⏱️ 90 Minutes A Night: The Stolen-Hours Cadence

> **You'll walk away with:** a realistic operating rhythm for the busiest version of you — so you make real weekly progress in stolen hours instead of waiting for a free weekend that never comes.

The #1 thing standing between members and finishing isn't difficulty — it's **time.** Most people here are doing this in stolen hours: after the kids are down, before work, on a lunch break. The promise everyone makes and almost nobody keeps is "I'll go hard on the weekend." The people who win here aren't the ones with the most time; they're the ones who keep showing up for 90 minutes and don't restart.

### One build at a time (kill shiny-object syndrome)

The fastest way to make zero progress is to start over every time you find a "better" idea. "Starting over when I find a better idea" is the single fastest way to stay exactly where you are. **Pick one build. Finish it. Ship it. Then move.** A shipped ugly thing beats a perfect thing you restarted four times.

### The 90-minute session shape

- **5 min** — open your project, read your last note to yourself ("Tomorrow: do X"). No decisions needed. You already know what's next.
- **70 min** — one small, specific move. Not "build the app." One screen, one feature, one fix. Use **plan mode** so Claude scopes it before touching anything.
- **10 min** — commit the work, write a one-line note for tomorrow.
- **5 min** — post one thing in the community (a screenshot, a question, a win).

### Progress is weekly, not nightly

The aim is shipping **one real thing a week** — a page, a bot, a post. Not 50 things. Pick 52 of those and you're a different person at the end of the year.

The whole cadence in one line: **one build, one small move a night, checkpoint, leave a note for tomorrow.** Boring, repeatable, and it compounds.

**Done when:** you've picked your ONE current build, you know the 90-minute session shape, and you've written your next single move down for tomorrow.

### Prompt

> I get about 90 minutes a night and I keep starting over on new ideas. Help me lock in ONE build to finish. Ask me what's already half-done, what's closest to shippable, and what I'd actually be proud to post. Pick one for me, then break it into small nightly moves I can each do in 75 minutes. End by giving me tonight's single move so I can start right now.

## 🧪 (Optional) Inside the Terminal: A Friendly First Look

> **You'll walk away with:** enough comfort to open a terminal, read what it's telling you, and move around in it, so the black screen stops being scary if you ever choose to use it.

First, the important part: this lesson is **completely optional**. The desktop app does everything in this course, and most members never open a terminal once. Still here? Good. The terminal is not what the movies made it.

### What the terminal actually is

It's a text conversation with your computer. That's the whole thing. Instead of clicking buttons, you type a short instruction, press enter, and the computer does it. The desktop app puts a friendly face on this. The terminal is the bare dashboard underneath. You are not "coding" when you use it. You're typing plain instructions, same as you type in English to Claude. Identical power in the app.

### How to open one

- **Windows:** click Start, type "Terminal" (or "PowerShell"), press enter. A panel opens at the bottom. This is the handiest one because your code and your terminal sit side-by-side.

### Reading the screen (the part nobody explains)

- **The prompt** — the line with a blinking cursor in it. That's your turn. You type what you want, press enter, and pass control to the computer. When it comes back, it's your turn again.
- **"Nothing happened"** — silence. You sent a command and no message appears. This is the single biggest source of panic, and it almost always means it **worked.** The terminal stays quiet when things go right and only speaks up when something is worth telling you. Silence is success.
- **"Something is running"** — the cursor sits and nothing is happening, a job is still in progress. Let it finish. When your prompt comes back, it's done.
- **An actual error** — Real errors are usually a block of text, or a line starting with words like "error" or "command not found." They look scary. Copy the text, paste it to Claude, and it'll tell you the one-line fix.

### To close it

Press the X when you're done typing, and press enter or just close the window. Nothing breaks. Closing a terminal while Claude is running stops Claude — same as closing any app.

### The only two ways to move around

That covers about 80 percent of moving around. Everything beyond you'll let Claude handle.

- `cd foldername` — moves you into a folder (`cd ..` means change directory, go up one level)
- `cd my-business` — walks you into your project
- `ls` — lists what's in the folder you're standing in, so you can see where you are

**Done when:** you've opened a terminal, know what the prompt is, and can use `cd` and `ls` to get to your project folder.

**To get going:**

- `cd my-business` — lands you in your project folder
- `claude` — launches Claude Code right there in the terminal. That's the magic word. From this point on, you're just talking to Claude in plain English, same as the app.

**Once Claude Code is open, a few slash-commands to keep handy:**

- `/clear` — wipes the current conversation context and starts fresh. Use it when you want a clean slate. Worth knowing when you want a faster or more powerful one.
- `/model` — switch which Claude model you're using.
- `/resume` — resumes your last chat right where you left it. This one is genuinely great: close your laptop, come back tomorrow, type `/resume`, and Claude picks up mid-thought.

**You'll see Claude run these (just read along):**

- `ls data` — moves between folders
- `git status` — checks what's changed; `git commit` saves a checkpoint of your work
- `npm install` — adds a tool a project needs

When you see these scroll by, that's just Claude doing the plumbing. Read them like subtitles. You don't type them — Claude does.

### When it's actually worth using the terminal

- **Long or background jobs.** If something needs to run for a while, the terminal handles it without tying up your app.
- **When the app is being weird.** If the desktop app stalls, launching `claude` in a terminal is a reliable plan B.

None of these are required. They're just the times a member might reach for the terminal on purpose.

If none of this calls to you, close the terminal and stay in the app. You are not missing anything. The people shipping the most in this community are split right down the middle between app and terminal, and the builds look identical.

**Done when:** you know the short list you actually type (`cd`, `claude`, `/clear`, `/model`, `/resume`, and `!`), and the few moments the terminal is worth opening.
